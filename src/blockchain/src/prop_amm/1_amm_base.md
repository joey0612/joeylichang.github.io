# Market Microstructure Fundamentals

做市理论完全不依赖区块链，但链上做市的每一个设计权衡——价差压多窄、报价要多新鲜、怕不怕被套利——都来自这套理论。本部分建立四个核心概念：价差、逆向选择、库存风险、订单流，并推出贯穿全文的中心命题：**报价新鲜度可以兑换成更窄的价差**。

## 1. Maker, Taker, and the Bid-Ask Spread(价差)

做市商（market maker）的生意模式：**同时挂出买价（bid）和卖价（ask），无论对手方是来买还是来卖都接单，赚取两者之间的差额**。这个差额叫价差（spread），bid 与 ask 的中点叫中间价（mid price）。

- **Maker（挂单方）**：先把价格摆出来等人来成交的一方。做市商基本总是 maker——他"制造"（make）价格。
- **Taker（吃单方）**：看到价格后决定按此成交的一方——他"拿走"（take）价格。链上语境中，taker 泛指来 swap 的用户，或聚合器替用户路由过来的订单。

价差的计量单位是**基点（bp, basis point）= 万分之一 = 0.01%**，换算公式：

```
价差(bp) = (卖价 − 买价) ÷ 中间价 × 10000

损失金额 = 交易金额 × bp 数 ÷ 10000
```

例：一笔 100,000 USDT 的交易，1bp = 10 USDT，5–10bp = 50–100 USDT。几个基准数字值得建立手感：Binance 上 BNB/USDT 这类主流对的价差通常在 1–2bp 量级；Uniswap 经典手续费率 0.3% = 30bp；常见的滑点容忍设置 0.5% = 50bp。

价差越窄，taker 的成交条件越好；但价差是做市商的毛利来源，报多窄取决于他承担多大风险——这是本部分后面要展开的主线。

## 2. Depth(深度), Slippage(滑点), and Liquidity(流动性)

价差回答"价格好不好"，**深度（depth）**回答"这个价格能吃下多大的量"。两者相互独立：做市商完全可以报一个极窄的价差但只挂很小的量（后文会看到，Base 上的作恶者正是利用这一点欺骗聚合器）。

**滑点（slippage）**：订单量太大、把好价格吃完之后，实际平均成交价相对于牌价的劣化。深度越厚，同样大小的订单滑点越小。

**流动性（liquidity）**是以上所有维度的总称：想成交时，能不能**快速、大量、以接近牌价的价格**成交。

```
流动性好 = 价差窄 + 深度厚 + 滑点小
```

三者都需要做市商主动投入资本和承担风险，没有哪一项会因为另一项自动变好。

## 3. The Market Maker's Workflow

专业做市商（Wintermute、Jump 等）在 CEX 上的工作是一个毫秒级循环，四步：

1. **订阅行情（听）**：websocket 实时接收本所订单簿、成交流水，以及其他交易所、期货市场的行情。第一竞争力是"耳朵灵"。
2. **计算公允价（想）**：把所有信息喂进定价模型，得出内部的公允价估计（fair value）。这是各家的核心机密。
3. **挂撤单（报）**：围绕公允价两侧挂单。关键动作是**撤单**——公允价一变，旧挂单立刻变成错误报价，必须先撤再重挂。高频做市商的撤单量远大于成交量，撤单速度直接决定损失大小。
4. **对冲库存（平）**：成交后检查持仓，偏离目标就对冲（见 1.5），然后回到第 1 步。

这个循环是理解链上做市的参照系：①②④ 都在链下照常运转，**全部工程难题集中在第 ③ 步的移植上**——CEX 上撤单重挂是毫秒级、免费、必然按序执行的；链上"撤旧价挂新价"是一笔需要打包、排序、支付 gas 的交易。后文所有链上机制（Jito 小费、taker ordering、签名报价）本质上都是第 ③ 步的不同移植方案。

容易混淆的一个概念是预言机，与演技（oracle）是公开的价格搬运工。 它把链下已经形成的价格（通常聚合多家交易所/做市商的数据）签名后送上链，给借贷清算、衍生品结算这类合约当中立参考价。它是公共基础设施，输出的是一个大家都看得到的、单一的价。

关系可以这么排：价格发现发生在做市商们的定价模型里（他们的报价形成了市场价）→ 预言机把这个结果聚合、搬运上链 → 链上应用消费它。三个具体差异：

* 快慢：定价模型毫秒级、连续；预言机再快（Pyth pull 约 400ms）也是它的降采样快照
* 胖瘦：定价模型输出完整的"盘型"（公允价 + 价差 + 各档深度 + 库存倾斜）；预言机只输出一个干巴巴的参考价
* 私公：定价模型的输出是拿来赚钱的武器；预言机的输出是拿来被引用的公共品

## 4. 逆向选择: The Glosten-Milgrom Intuition

做市商最大的亏损来源不是价差不够宽，而是**和比自己知道更多的人交易**。Glosten-Milgrom 模型的直觉：做市商每天接待两种客人，但脸上不写字，分不出谁是谁。

- **不知情者（uninformed / noise trader）**：因自身需求来交易——换仓、用钱、定投。来的时机与"报价对不对"无关。做市商与他们成交稳赚价差。
- **知情者（informed trader）**：**只在报价错误时出现**。他知道真实价值已经变了（看到了新闻、看到了别处的价格、算得更快），报价 100 而他知道值 103 时才来买。与知情者的每一笔成交都是亏损。

关键在于知情者的出现**不是随机的**：报价正确时他不来，错误时必来——像苍蝇精确地只叮报价出错的瞬间。因此这部分亏损不是运气波动，是结构性的、只要挂着过期报价就必然缴纳的税。这个现象叫**逆向选择（adverse selection）**；被知情者吃掉过期报价，行话叫**被 pick off**；知情者主导的订单流叫 **toxic flow(毒流)**，与之相对的散户流叫 retail flow。

做市商的生存方式：**把价差当保险费**。既然分不出客人，就对所有人统一加价——价差中有一部分本质上是向不知情者收取的保费，用于覆盖被知情者收割的确定损失。由此得到模型最重要的结论：

> **客流中知情者占比越高、知情者的信息优势越大，价差必须越宽。反之，凡是能压缩知情者优势的机制，都能让价差收窄。**

## 5. Inventory Risk(库存风险)

库存风险与逆向选择相互独立——**即使世上没有一个知情者，它也存在**。

做市商的理想状态是两边倒手赚价差、自己不押方向。但成交随机到来：某段时间恰好卖给他的人多，他就被动积压了超出目标的仓位，实际上变成一个"被迫持有方向敞口的赌徒"——价格一跌，价差利润瞬间赔光。**持仓偏离目标后暴露于价格波动的风险，就是库存风险（inventory risk）。**

两种标准处理手段：

- **歪报价（skew）**：库存偏多时整体下移双边报价，用价格杠杆引导客流帮自己泄库存；
- **场外对冲**：链上/本所刚吃进的仓位，立刻在另一个市场（通常是 CEX）反向对冲，锁定价差利润、消灭方向敞口。"链上做市、CEX 对冲"是专业做市商的标准姿势。

推论：做市商天然偏爱**确认快**的交易场所——从成交到对冲之间的"裸奔时间"越短，库存风险越小。区分记忆：**逆向选择决定价差报多宽，库存风险决定敢挂多大的量、需要多快的对冲通道。**

## 6. Order Flow and Price Discovery

**订单流（order flow）是这个行业真正围绕组织的资产**——价格是人人可见的公共信息，订单流是"接下来价格会怎么动、以及与谁交易是安全的"的私有信息。它的价值有两层：

**第一层：流能预告价。** 价格是已发生之事的结果，订单流是正在发生的事本身。持续的扫货买单出现时，价格上涨尚未完成——流是因，价是果，看到因的人永远领先看到果的人。

**第二层：知道对手是谁，等于知道这单能不能安全地接。** 同样一张买单，来自散户钱包则是优质流（零逆向选择风险），来自套利机器人则是有毒流（接单必亏）。若有人能把散户流单独打包出售，做市商敢对这批流报出极窄价差——传统金融的 PFOF（payment for order flow，订单流付费）正是这个逻辑：做市商付费购买券商的散户订单流，因为"确认无毒"这个信息本身值钱。

**由此推出：谁握着订单流的入口，谁就握着可变现的权力。** 这条原理在后文反复出现——聚合器的守门人地位、builder 之间的私有订单流竞争、propAMM 的分销难题，全部是它的具体形态。

**价格发现（price discovery）**：一个资产"此刻值多少钱"这个信息最先在哪里形成。传导机制是一个自增强循环：

1. 新信息（和拥有它的灵通资金）总是流向交易成本最低的场所——价差最窄、深度最厚的地方；
2. 灵通资金的买卖行为本身就是信息，做市商据此调整报价——最新价格在此"被发现"；
3. 其他场所靠套利者搬运来跟上（见 2.2），永远慢半拍；
4. 定价权巩固该场所的流量引力，深度更厚、价差更窄，回到第 1 步。

市场因此分成两种角色：**出题人**（价格发现地）与**抄答案的**（价格跟随地）。抄答案的场所有个隐藏代价：它的做市商/LP 永远在被套利者用"已公布的答案"收割。加密市场的现状：**价格发现主要发生在 CEX（Binance 为首），链上池子是跟随者**——这是 CEX-DEX 套利存在的根源，也是链上被动 LP 系统性亏损的根源。

## 7. The Central Trade-off: Freshness Buys Spread

把价差拆开，它是三笔钱的总和：

```
spread ≈ 运营成本 + 库存风险补偿 + 逆向选择保险费
```

前两项相对固定，第三项是大头，也是唯一能被机制设计大幅压缩的变量。知情者收割做市商的唯一窗口是"报价已过期但仍然挂着"的时间段：

```
逆向选择成本 ≈ 报价过期窗口的长度 × 窗口内的价格波动 × 窗口内被成交的量
```

- 报价 10 秒才能更新一次：每次波动裸奔 10 秒，保险费必须收厚，价差报 20bp 自保；
- 报价 400ms 刷新、且更新保证排在成交之前：裸奔窗口趋近零，保险费趋近零，价差敢报 1–2bp。

这就是全文的中心命题：**报价新鲜度可以精确地兑换成更窄的价差——不是玄学，是保险精算：风险敞口的时间窗缩小多少，保费就能降多少。** 它还自带正反馈：价差窄 → 不知情的普通用户更愿意来 → 客流毒性下降 → 按 Glosten-Milgrom 价差可进一步收窄。

评估任何一条链能否承载高质量做市，可以直接用这个第一性原理检查三个参数：

```
链上可达到的报价新鲜度 ≈ f(出块间隔, 报价更新成本(gas), 排序保证)
   —— 多久能改一次价、改一次价多少钱、改价能否插在成交之前
```

后续全部内容，都是不同的系统在这三个参数约束下求解同一道题。
