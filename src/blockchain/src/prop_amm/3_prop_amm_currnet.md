# PropAMMs in Production: Solana, Ethereum, Base

## 1. What Is a PropAMM

PropAMM（proprietary AMM，自营做市 AMM）：**专业做市商完全私有地运营链上池子——链下定价引擎实时决定报价与曲线形状，通过高频链上更新维护，不接受外部 LP。** 与前代的区别：

- vs 传统 AMM：曲线从"由存款和 k 定死"变成"由做市商实时遥控"；
- vs Lifinity：定价源从公共 oracle 换成做市商私有策略（更快、更准、带完整盘型）；
- vs RFQ：报价放在链上合约里——可组合、聚合器可模拟——而非按 taker 指名签发。

"不接受外部 LP"是定义性特征：盈亏全归运营方，被收割的刀落在自己身上，才有毫秒级刷新报价的动力——这是与"散户 LP 集体躺平被抽血"的被动池子在激励结构上的根本分野。谱系：Lifinity（2022，oracle 定价先驱）→ SolFi、HumidiFi、BisonFi、TesseraV（2024–2026，完全私有定价）。

propAMM 对基础设施的核心诉求只有一句话：**"我的报价更新必须能插在 taker 成交之前"**——即 1.3 节工作流第 ③ 步（挂撤单）的链上等价物。三条链用三种完全不同的方式回答了这个诉求，构成一条信任光谱：链的原生属性（Solana）→ 单一公司的承诺（Ethereum/Titan）→ 承诺缺位下的乱象（Base）。

## 2. Solana: Chain-Native Ordering

**背景**：Solana 每约 400ms 一个 slot，由提前一个 epoch 公示的 leader schedule 指定唯一出块者；交易不进公开 mempool，直接转发给即将出块的 leader（Gulf Stream）。**验证者即排序者，不存在独立的 builder 角色。** Jito 在此之上运营区块空间拍卖：交易打包成 bundle 附带小费（tip），按小费竞争区块内优先位置，原子执行、失败不上链。

propAMM 在 Solana 的成功直接依赖四个链层条件：

1. **无 builder 信任层**：排序权在协议指定的 leader 手里，做市商不需要信任任何第三方公司"不作恶"；
2. **leader 可预测**：schedule 提前公示,做市商精确知道下一个 slot 谁出块,把报价流定向推送给对应验证者/relayer——不需要像 EVM 链那样赌某个 builder 的私有 API；
3. **Jito 拍卖成熟**：做市商用小费竞得"先取消再更新"的区块头部位置,在 taker 交易落地前完成最后一次报价刷新——2.4 节"拍卖优先权"思想的生产级实现;
4. **Jupiter 的中立分销**：被 Jupiter 收录 ≈ 拿到全平台路由,冷启动只有一道门。

工程细节的金融含义:HumidiFi 把一次报价更新压缩到 **143 个计算单元（CU,Solana 的 gas）**——参与拍卖的标的物越轻,竞得黄金位置所需小费越低,等于用地板价长期锁定"改价插在成交前"的权利。对照 1.7 的公式:出块 400ms(改价快)+ 更新 143 CU(改价便宜)+ Jito 拍卖(改价排在前)——三个参数全部拉满,实际逆向选择窗口逼近零,价差可以压到与 CEX 竞争的水平。

**市场现状（2026 Q1）**：propAMM 占 Solana DEX 总成交量 **60% 以上**,全面压制 Orca/Raydium/Meteora 等传统 AMM。头部:HumidiFi(日均约 4.6 亿美元;SOL-稳定币单一交易对日均可超 10 亿美元,直接与 Binance 竞争该对定价权)、BisonFi(日均约 4.3 亿美元,环比 +362%)、TesseraV(日均约 1.8 亿美元,Wintermute 运营——传统做市巨头把 CEX 能力搬上链的标志)。

## 3. Ethereum: Builder-Committed Ordering (Titan)

**背景**：以太坊 PBS 把产块拆成三角色——builder 组装区块（决定排序），通过 relay 向 proposer（轮值 validator）盲拍，proposer 把签名权卖给出价最高者。builder 的竞争力核心是**私有订单流**：流多者组的块值钱、赢块率高、吸引更多流——赢家通吃的正反馈使 builder 市场高度集中，Titan 是头部之一。以太坊 12s 出块、gas 昂贵，按 1.7 的公式本不适合 propAMM——它的路径完全不靠链本身，靠头部 builder 主动开放排序权限。

**Titan 的 taker ordering（2026 年 5 月上线）**：白名单做市商把签名报价流式推送给 Titan；Titan 在构建区块时保证——**凡吃到该做市商流动性的 taker 交易，其前面必然排着最新一条适用的报价更新**；并提供可配置的"新鲜度缓冲期"（freshness buffer）防止 taker 利用延迟差捡过期价。做市商的两难（报价要晚到达以压缩逆向选择窗口，又要排在 taker 前面保证按新价成交）被一纸承诺同时解决。

数据（上线约 3 周）：累计成交 5.46 亿美元+、6.8 万+ 笔 swap；BTC/ETH/稳定币主要对的部分价格区间报价已紧于 Binance 与主流 DEX；Kyber 聚合器已接入。

**结构性限制**，每一条都源于"保证来自一家公司"：

- **覆盖率天花板**：承诺只在 Titan 赢得竞标的区块里有效。若 Titan 只赢 40% 的块，做市商在另外 60% 的块里回到不设防状态——且 builder 竞标每块临场开奖（对比 Solana leader 提前公示），做市商无法预知哪个块有保护，只能按概率整体定价：报宽价差、装合约保险丝（超时拒绝成交）、或少挂深度，每一样都在侵蚀 propAMM 的立身之本。**保证的覆盖率 = 一家公司的市占率，一个随行情波动的数字。**
- **垄断飞轮**：做市商希望 Titan 赢更多块（自己的保护覆盖率更高）→ 把独家报价流给 Titan → Titan 的块更值钱 → 赢块率上升 → 吸引更多做市商。每个参与者的理性选择都在推动 builder 市场向一家独大滑去，而 builder 垄断意味着排序、审查、准入集中于一个私人实体。
- **准入与信任**：API-key 白名单制——谁能做市由一家公司批准；做市商还需信任 Titan 不利用看到的报价流自营抢跑。这是 Solana 路径没有的额外信任层，目前也没有形成多 builder 共享的中立标准。

## 4. Base: Sub-Block Preconfirmations and Their Abuse

**背景**：Base 是单一 sequencer 排序的 L2。Flashblocks 把 2s 的区块切成 10 个约 200ms 的子块，sequencer 每 200ms 发布一次增量预确认——应用可基于最新子块状态决策，等效把感知延迟压到 200ms 级。这让报价更新足够频繁的 propAMM 在 EVM 上变得可行，但**没有任何 taker ordering 语义**——更新快了，顺序仍无保证。

规模先行：0x（Base 上最大的聚合器之一）已接入 5 个 propAMM、5 个在评估，propAMM 贡献其 Base Swap API 成交量的 40–50%，单个 propAMM 近三个月成交 12.5 亿美元。

随后 0x 的实证研究（"PropAMM Shenanigans"）揭露了两种系统性作恶——本质都是 2.5 节"模拟-成交缝隙"的武器化：

**模式一：利用 Flashblock 分块的聚合器诱导。** 做市商在每个区块**最后一个** flashblock（约 200ms 窗口）报出诱人价格；聚合器订阅子块流、基于这个末端状态做路由决策；taker 交易落到下一个区块**第一个** flashblock 时，做市商已把价格改差。诱饵价从头到尾只存在于"被观察"的维度——它的存活时间（200ms）远短于任何 taker 的反应时间，**从未真正暴露在可被成交的风险里，是零风险骗术**。证据的统计方法论值得记住：某 propAMM 的报价更新落在区块最后 10% 位置的概率高达 **97.4%**，且不随成交量、方向变化——排除正常做市行为，证明刻意为之。影响：每笔 5–10bp，单一来源每月约 50 万美元。

反事实检验（这个模式对架构的依赖）：若没有 flashblocks、只有 2s 整块，诱饵价必须作为区块最终状态在链上完整暴露约 2 秒——全市场的套利机器人都来得及打它，做市商必须在下一块抢到排序才能全身而退。零风险魔术退化为高风险赌博，生意不成立。**模式一是 Base 特定架构（状态可见粒度远细于 taker 反应时间）的寄生物。**

**模式二：确认窗口内的价差拉宽。** 先报约 2bp 的极窄价差赢得聚合器路由；taker 签名提交后、交易在途的窗口内，突然把价差拉宽到 8–16bp；taker 按拉宽后的价格成交。成立条件只有一个：**做市商改价速度 > taker 交易的确认延迟**——与 flashblocks 无关，与链无关（Solana 基金会的交易研究团队记录过同样行为）。这个条件恰恰是 propAMM 的定义性能力本身：**报价新鲜度这把刀，朝向套利者时叫压缩逆向选择窗口，掉头朝向自己的客户时就叫模式二**。它没有架构层面的疫苗，只有机制层面的：把报价与结算用密码学焊死（签名报价），或给 taker 装底线（intent 的最少到手量；普通滑点容忍通常设在 50bp，挡不住 8–16bp 的精细收割）。

0x 选择主动切断作恶源——随即落入 2.5 节的囚徒困境：谁纵容作恶，谁的展示报价就更好看、就能抢到更多路由量。单方面做好人每天都在为原则支付流量代价。

## 5. Comparative Notes: The Trust Spectrum

三条链对 propAMM 核心诉求（"报价更新插在 taker 成交之前"）的回答：

| | Solana | Ethereum (Titan) | Base |
|---|---|---|---|
| 排序权归属 | 协议指定的 leader（可预测） | builder 竞标市场（每块开奖） | 单一 sequencer |
| 排序保证来源 | 链原生属性 + Jito 拍卖 | 一家 builder 的承诺 | 无 |
| 保证覆盖率 | ≈ 全部区块 | = Titan 的赢块率 | 0 |
| 额外信任层 | 无（Jito 为准公共设施） | 信任 Titan 不作恶、不抢跑 | — |
| 做市商准入 | 无许可（分销靠 Jupiter 收录） | API-key 白名单 | 各聚合器自行接入 |
| 分销 | Jupiter（中立、一家独大） | Kyber 等逐个接入 | 0x 等，已现囚徒困境 |
| 实际状态 | propAMM 占 DEX 量 60%+ | 起步约 3 周、5.46 亿美元 | 量不小，但报价-结算缝隙被系统性利用 |

一条信任光谱贯穿三个案例：**协议规则（无需信任）→ 公司承诺（信任一家 builder）→ 承诺缺位（信任荡然无存，乱象丛生）**。同时三个案例共同验证了 Part I 的中心命题及其阴面——新鲜度换窄价差在 Solana 兑现为与 CEX 竞争定价权的能力，在 Base 则显形为同一能力被掉转刀口的模式二。机制设计的任务，就是让这把刀只能朝一个方向挥：要么用排序保证消灭做市商的过期风险（Solana/Titan 路线），要么用密码学签名消灭 taker 的结算漂移（RFQ/intent 路线）——而任何一条新的链想引入 propAMM,都需要在这条信任光谱和这两条技术路线中找到自己的坐标。
